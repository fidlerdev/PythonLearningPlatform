## Построчное выполнение

Кнопка «По шагам» останавливает Python перед каждой исполняемой строкой.
Подсвеченная строка выполнится по кнопке «Следующая строка»; циклы повторно
проходят строки тела. Карта показывает результат уже выполненных команд.
«Стоп» уничтожает worker, редактирование кода отменяет текущий запуск.
Частично выполненную программу нельзя отправить на проверку.

Используется режим `Sk.debug` и обработчик приостановок Skulpt, а не повторный
запуск префиксов программы. Ожидание пользователя исключено из лимита времени;
таймер загрузки/вычисления выключен на паузе. Действуют ограничения 1000 действий
и 10 000 пошаговых остановок. Контрольные сценарии: `robot-stepping.spec.ts`
и `scripts/check-robot-content.mjs` (настоящий Python runtime).

## Прогресс и доступ учеников

`GET /api/progress/` возвращает личную панель: прогресс по актуальным версиям,
первые успешные решения без подсказок, исправленные решения, достижения и следующее
незавершённое задание. Рекомендация открывает конкретный блок через
`#/lesson/<release>?block=<block>`. Другой ученик не может запросить чужую статистику.

`GET /api/author/students/<id>/progress/` доступен только преподавателю этого ученика
(либо суперпользователю). Содержит статусы заданий, сигналы поддержки после двух
безуспешных попыток и активность за семь дней. Подсказки не штрафуются. Повторная
успешная отправка не увеличивает число решённых заданий. Решение считается
самостоятельным, если на момент **первой успешной попытки** не было подсказок;
ошибочные попытки до этого не мешают самостоятельности. Публикация новой версии
обновляет текущий маршрут, но не удаляет историю и ранее полученные достижения.

`POST /api/author/students/<id>/password/` принимает `{ "password": "…" }`,
проверяет права, CSRF и стандартные требования Django, сохраняет только хеш.
Старые сессии ученика становятся недействительны. Получить текущий пароль нельзя.
При создании/смене новый пароль можно показать и скопировать: он существует только
в состоянии формы до её закрытия/смены ученика/обновления страницы, не записывается
в localStorage, логи или ответы API. Имена и пароли из тестов — тестовые данные.

## Окружение

- Python 3.12–3.14 и uv.
- Node.js 22.12+ и npm.
- Docker Compose для запуска с PostgreSQL.

Python-зависимости описаны в `backend/pyproject.toml` и зафиксированы в
`backend/uv.lock`. Для интерфейса используется `frontend/package-lock.json`.

## Локальный запуск без Docker

Создайте `.env` в корне на основе [.env.example](../.env.example).
Для локального HTTP нужен `DJANGO_DEBUG=1`. Без `POSTGRES_HOST` сервер
использует SQLite; при заданном `POSTGRES_HOST` — PostgreSQL.

В первом терминале:

```bash
cd backend
uv sync --locked
uv run --env-file ../.env manage.py migrate
uv run --env-file ../.env manage.py create_teacher teacher --name "Преподаватель"
uv run --env-file ../.env manage.py import_lessons content/robot-introduction.json --owner teacher --publish
uv run --env-file ../.env manage.py import_lessons content/robot-challenges.json --owner teacher --publish
uv run --env-file ../.env manage.py runserver 127.0.0.1:8000
```

Во втором:

```bash
cd frontend
npm ci
npm run dev
```

Интерфейс доступен на http://127.0.0.1:5173. Vite проксирует `/api` к Django,
поэтому интерфейс и API работают через один origin. Адреса локального
фронтенда включены в доверенные origins CSRF только для режима разработки.

`create_teacher` запрашивает пароль скрытым вводом; для автоматизации
можно передать `TEACHER_PASSWORD`. Команда не перезаписывает существующие
учётные записи. Для Django admin создайте отдельного администратора:

```bash
uv run --env-file ../.env manage.py createsuperuser
```

## Работа с контентом

1. Создайте задание в библиотеке: условие, карту или варианты ответа, правила и подсказки.
2. Соберите урок из объяснений и ссылок на задания; настройте порядок блоков.
3. Сохраните черновик и опубликуйте версию.

Задание можно включать в разные уроки. Публикация копирует содержание и правила
в снимок. Изменения библиотеки применяются к будущим публикациям. Попытки
и черновики привязаны к конкретной версии; автоматического переноса прогресса
на новую версию пока нет.

Импорт JSON добавляет новые объекты и выполняется атомарно. Повторный импорт
создаёт новые уроки, поэтому для обычного редактирования используйте конструктор.
Схемы и примеры — в [модели контента](CONTENT_MODEL.md).

## Выполнение и проверка Python

Код ученика выполняется в Worker внутри iframe с `sandbox="allow-scripts"`,
без `allow-same-origin`. Доступен только модуль `robot`. Есть ограничения
времени, количества действий и объёма вывода; остановка удаляет среду выполнения.
Сервер Django не выполняет присланный Python через `exec` или `eval`.

Команды `forward()`, `turn_left()`, `turn_right()`, `can_move()` и `at_goal()`
регистрируются в среде как встроенные. Ученик начинает писать решение сразу,
без `from robot import *`. Скрытый Python-префикс не добавляется, поэтому номера
строк ошибок совпадают с редактором. Явный импорт остаётся совместим со старыми
программами. В редакторе старый служебный префикс скрывается без изменения
опубликованных версий и истории попыток.

Skulpt 1.2.0 загружается с `cdn.jsdelivr.net`, поэтому для запуска робота нужен
интернет. Это ограниченная реализация Python. Для автономного развёртывания
потребуется поставлять runtime с собственного сервера.

Тесты и короткие ответы проверяются сервером. Для робота сервер воспроизводит
журнал команд, проверяет стены, границы, цель и бюджет маршрута. AST используется
для подсчёта записанных команд и базовой проверки наличия цикла.

Журнал приходит из браузера и не подтверждает независимо, что именно присланная
программа его создала. Такие попытки отмечаются `verification=client_trace`.
Для экзаменов нужен отдельный изолированный серверный исполнитель. Проверка
конструкций и бюджета кода — учебная; она не доказывает семантику произвольной
программы и не защищает от намеренного обхода метапрограммами.

## Проверки

Сервер:

```bash
cd backend
uv run --env-file ../.env manage.py check
uv run --env-file ../.env manage.py makemigrations --check --dry-run
uv run --env-file ../.env pytest
```

Проверки схем и алгоритмов без внешних Python-зависимостей:

```bash
cd backend
python3 -m unittest tests.test_domain tests.test_challenges -v
```

Интерфейс и эталонные программы:

```bash
cd frontend
npm ci
npm run build
cd ..
node frontend/scripts/check-robot-content.mjs
```

Браузерный сценарий:

```bash
cd frontend
npx playwright install chromium
TEST_TEACHER_USERNAME=teacher TEST_TEACHER_PASSWORD='test-account-password' npm run test:e2e
```

Для E2E нужен работающий backend и отдельный тестовый преподаватель. Тест
добавляет ученика, задание и урок в подключённую БД — используйте БД разработки.
Он проверяет прохождение, подсказку и восстановление ответа и прогресса
в новой браузерной сессии.
