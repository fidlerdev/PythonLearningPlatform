# Шаг — интерактивное изучение Python

Первая реализация платформы: Django + DRF, PostgreSQL, React + TypeScript,
CodeMirror и браузерное выполнение Python через Skulpt. Python-зависимости
управляются через **uv**, конфигурация — `backend/pyproject.toml`.

## Что реализовано в коде

- Вход и выход, серверные сессии, CSRF-защита, роли ученика и преподавателя.
- Библиотека самостоятельных объектов-заданий: тест, короткий ответ и робот.
- Конструктор уроков из упорядоченных блоков: объяснение или ссылка на задание.
- Визуальное редактирование карты: размеры, старт, направление, цель, стены.
- Проверка достижимости цели при сохранении задания.
- Черновик и публикация: опубликованный урок хранит отдельный снимок заданий.
- Каталог опубликованных уроков и страница прохождения с редактором Python.
- Робот: `forward()`, `turn_left()`, `turn_right()`, `can_move()`, `at_goal()`;
  циклы `for` / `while`, анимация движения, остановка и сброс.
- Проверка тестов и коротких ответов на сервере; проверка маршрута робота по
  журналу команд; необязательное требование использовать цикл.
- Индивидуальные черновики, попытки, открытые подсказки и выполненные задания.
- Создание учеников и просмотр их попыток преподавателем.
- Импорт уроков и заданий из переносимого JSON-формата.

Первый урок — «Робот и сила повторений»: эксперимент, объяснение цикла,
предсказание результата, применение цикла и перенос идеи на новую карту.
Его содержимое находится в `backend/content/robot-introduction.json`, а не в React.

Это первый этап MVP. Пока нет Turtle, назначения уроков отдельным ученикам,
восстановления пароля и самостоятельной смены пароля. Все опубликованные уроки
доступны всем вошедшим пользователям. Администратор может менять пароли через
Django admin. Прогресс и черновики привязаны к версии: новая публикация не переносит
автоматически результаты старой версии; прежняя версия остаётся доступна по URL.

## Локальный запуск через uv

Требуется Python 3.12–3.14, uv, Node.js 22.12+ и доступ к реестрам пакетов.
Для быстрого запуска без контейнеров используется SQLite; PostgreSQL включается
переменной `POSTGRES_HOST`.

Создайте `.env` в корне на основе `.env.example`. Для локального HTTP нужен
`DJANGO_DEBUG=1`. Не используйте пример настроек для публичного размещения.

В первом терминале:

```bash
cd backend
uv sync
uv run --env-file ../.env manage.py migrate
uv run --env-file ../.env manage.py create_teacher teacher --name "Преподаватель"
uv run --env-file ../.env manage.py import_lessons content/robot-introduction.json --owner teacher --publish
uv run --env-file ../.env manage.py runserver 127.0.0.1:8000
```

`create_teacher` запросит пароль скрытым вводом. Для автоматизации можно передать
его через `TEACHER_PASSWORD`. Существующие учётные записи команда не перезаписывает.
Импорт повторно создаёт новые уроки; это явная операция добавления контента.

Во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте http://127.0.0.1:5173, войдите как преподаватель и создайте ученика
на вкладке «Конструктор → Ученики». Для административной панели можно отдельно
создать администратора через `uv run --env-file ../.env manage.py createsuperuser`.
API и интерфейс работают через один origin благодаря прокси Vite.

## Запуск с PostgreSQL в Docker

```bash
docker compose up --build -d
docker compose exec backend uv run --no-sync manage.py create_teacher teacher
docker compose exec backend uv run --no-sync manage.py import_lessons content/robot-introduction.json --owner teacher --publish
```

Интерфейс: http://127.0.0.1:5173. Данные PostgreSQL сохраняются в отдельном volume.
Compose предназначен для разработки; публичное развёртывание, HTTPS,
прокси для статики и резервное копирование нужно настроить отдельно.

## Как создавать уроки

1. Откройте библиотеку заданий в конструкторе.
2. Создайте задание: условие, варианты ответа или карту робота, правила и подсказки.
3. Сохраните его в библиотеке.
4. Создайте урок: добавляйте объяснения и задания из библиотеки, меняйте порядок.
5. Сохраните черновик и опубликуйте урок. Он появится в каталоге учеников.

Одно задание можно включать в несколько уроков. Изменение задания меняет
библиотеку и будущие публикации. Уже опубликованные версии остаются прежними.
Кнопка публикации создаёт новую версию, даже если содержание не менялось.
Ученические результаты относятся к конкретному блоку конкретной версии.

Структура объектов и формат импорта описаны в [docs/CONTENT_MODEL.md](docs/CONTENT_MODEL.md).
Полная концепция — в [PROJECT_PLAN.md](PROJECT_PLAN.md).

## Выполнение и проверка Python

Python выполняется в Worker внутри `sandbox="allow-scripts"` iframe без
`allow-same-origin`. Среда не получает доступ к родительскому документу и сессии.
Доступен только модуль `robot`; код ученика не выполняется на сервере через `exec`.
Есть ограничения времени, количества команд и объёма вывода; остановка удаляет
iframe вместе со средой выполнения.

Skulpt 1.2.0 загружается с `cdn.jsdelivr.net`: для запуска робота нужен интернет.
Это ограниченная реализация Python, а не полная совместимость с CPython.
Перед публичным развёртыванием следует поставлять проверенную копию runtime
со своего сервера вместо зависимости от доступности CDN.

Тесты и короткие ответы проверяются независимо на сервере. Для робота сервер
воспроизводит присланные команды, проверяет стены, границы и достижение цели,
а наличие цикла проверяет через AST без выполнения кода. Этот журнал приходит
из браузера и не подтверждает независимо, что именно присланная программа его
создала. Такие попытки имеют `verification=client_trace`. Это учебная обратная
связь; для экзаменов нужен отдельный изолированный серверный исполнитель.
Проверка наличия цикла — базовая: она не доказывает, что цикл управляет движением.

## Проверки

Без внешних Python-зависимостей:

```bash
cd backend
python3 -m unittest tests.test_domain -v
```

С установленными зависимостями:

```bash
cd backend
uv run --env-file ../.env manage.py check
uv run --env-file ../.env manage.py makemigrations --check --dry-run
uv run --env-file ../.env pytest
```

Проверка интерфейса:

```bash
cd frontend
npm run build
npx playwright install chromium
TEST_TEACHER_USERNAME=teacher TEST_TEACHER_PASSWORD='your-test-password' npm run test:e2e
```

Для E2E нужен работающий backend и отдельный тестовый преподаватель. Тест создаёт
нового ученика, задание и урок в подключённой БД; используйте БД разработки.
Проверяется прохождение опубликованного урока, подсказка и восстановление
индивидуального результата и ответа в новой браузерной сессии.

### Что удалось проверить в среде разработки агента

Прошли 22 автономных теста схем контента и проверки решений, синтаксическая
компиляция Python и TypeScript/TSX, проверка JavaScript среды и `docker compose config`.
Полные API-тесты, сборка интерфейса и браузерный запуск ещё не выполнены:
реестры PyPI/npm недоступны, Django и CodeMirror отсутствуют в локальном кэше,
а доступ к Docker daemon запрещён средой.

`uv.lock` и `package-lock.json` пока не созданы: они должны быть получены
настоящим разрешением зависимостей через `uv sync` и `npm install` при доступной сети.
После этого lock-файлы нужно сохранить в репозитории; в CI использовать
`uv sync --locked` и `npm ci`.
